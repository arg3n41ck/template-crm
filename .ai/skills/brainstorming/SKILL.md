# Brainstorming

Project AGENTS.md, actual source and explicit user intent override generic workflow assumptions. Load only for the matching task.

1. Read the brief, existing architecture and constraints. State the goal, non-goals and material assumptions.
2. Ask one consequential question at a time only when a wrong assumption risks rework or safety. Do not turn a clear small task into a mandatory interview.
3. Compare a small number of feasible approaches using complexity, user experience, maintainability and constraints. Recommend the simplest suitable one.
4. Record the chosen design, acceptance criteria and verification approach. Obtain approval before resolving consequential ambiguity or starting work when the user asked only to brainstorm.
5. Use project-kickoff for a new product and feature-architecture for module boundaries; avoid duplicating their documents. Hand the approved design to writing-plans when execution needs multiple steps.

Output: decision/alternatives, assumptions and acceptance criteria. Explicitly approved implementation does not require another ceremonial approval.
